# Rugby HQ Integration Map

The prior Pocket PT architecture maps naturally to Rugby HQ.

## Command Center
Show decisions and exceptions:
- safety holds
- readiness modifications
- speed-exposure gaps
- overdue retests
- programme conflicts
- priority changes
- low-confidence data

Avoid dashboard clutter.

## Team Roster
Add:
- physical-priority chip
- availability
- test freshness
- target level
- state: DEVELOP / MAINTAIN / RESTORE / DE-EMPHASIZE

## Player Development
Physical Performance subareas:
- body profile
- strength
- power
- acceleration
- MSS
- conditioning / MAS
- RSA / RHIE
- movement
- game-demand fit
- training state

## Rugby Readiness
Capture:
sleep, fatigue, soreness, stress, mood, mental fatigue, fueling, hydration, match minutes, running/contact load.

## Competency Graph
Keep separate domains:
- rugby skill
- exercise skill
- movement capacity
- training exposure
- coach capability

Do not collapse them into one universal score.

## Training Planner
Use:
TEAM PROGRAMME + POSITION GROUP + INDIVIDUAL MODIFIER

Planning order:
phase → mesocycle → microcycle → session → exercise/drill → dose → actual → response.

## Match & Selection
Surface context, not automatic selection:
availability, workload, exposure, current priorities, confidence/freshness.
Do not let a hidden physical score choose the XV.

## Player Welfare
Reuse the existing “Recognize · Remove · Refer” safety philosophy for concussion and other hard medical gates.

## Data/Intelligence layer
Canonical athlete timeline + rule registry + confidence engine + demand profiles + planned-vs-actual + AI explanation.
