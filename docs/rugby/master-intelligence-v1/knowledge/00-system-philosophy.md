# Rugby HQ System Philosophy

Rugby HQ is a coaching decision-support system, not a generic workout generator.

## Core loop
ATHLETE PROFILE + POSITION + LEVEL + TARGET LEVEL + ASSESSMENTS + INJURY/HEALTH + READINESS + MATCH CALENDAR + TRAINING AGE + GAME DEMANDS
→ PRIORITIES
→ PERIODISATION MODEL
→ MESOCYCLE
→ MICROCYCLE
→ TEAM TEMPLATE
→ POSITION-GROUP MODIFIERS
→ INDIVIDUAL MODIFIERS
→ PLANNED WORK
→ ACTUAL WORK
→ GPS/VBT/RPE/READINESS/PERFORMANCE RESPONSE
→ ADJUST / RETEST / REFER

## Non-negotiables
- Profile before prescription.
- One datapoint never equals a conclusion.
- Preserve raw data, protocol, units, device/assessor, date and confidence.
- Same-protocol longitudinal comparison is preferred.
- Position is a modifier, not a stereotype.
- Current level and target level can both matter.
- Not all qualities can be maximized simultaneously.
- Every quality can be classified as DEVELOP, MAINTAIN, RESTORE or DE-EMPHASIZE.
- Training recommendations must be explainable: recommendation → why → evidence → confidence → what would change the decision.
- Medical/safety gates override optimization.
- AI is an explanation and interaction layer; the rules/data layer determines what is allowed, blocked, prioritized or modified.
- Coach override is permitted for coaching decisions and must be logged; medical and safeguarding restrictions are not casual coach overrides.

## Central object
The central product object is the athlete timeline, not the programme. Assessments, training, matches, readiness, injury/health status, movement observations, GPS, VBT, video, coach notes, competencies and recommendations all append to the timeline.

## Priority scaffold
A transparent planning scaffold can rank:
Demand Importance × Gap Magnitude × Evidence Confidence × Trainability × Timing Opportunity × Readiness Modifier, subject to Safety Gates.

This is not a validated medical probability equation. It is a configurable planning aid.
