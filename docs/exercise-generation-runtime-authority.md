# Exercise generation runtime authority

## Authoritative flow

`exercise-generation/sources/*.json` is the only human-maintained normalized exercise-content source. Generation resolves applicable inheritance, capability, threshold, and template inputs once into a canonical profile. Runtime, review, and translation adapters consume that in-memory profile; adapters must not reconstruct exercise content. `public/exercise-metadata.js` is generated from the browser-compatible template and the canonical Push-Up runtime adapter. The template intentionally contains no Push-Up definition.

Generated files carry a do-not-edit notice. Run `npm run generate:exercise-profiles`; never edit runtime or generated profile artifacts. `npm run verify:generated-artifacts` runs generation twice and compares all authoritative generated bytes.

## Version policy

- `schemaVersion` identifies the source/canonical contract.
- `sourceVersion` is incremented by a human for a material normalized-source revision.
- `profileVersion` equals `sourceVersion`; it therefore changes only with a deliberate source revision.
- `generatorVersion` changes for canonical generator behavior.
- `rulesVersion` changes for inheritance or semantic rules.
- `capabilityRegistryVersion` changes for capability/threshold registry behavior.

No generation command increments versions. A no-op is byte-identical.

## Fingerprint boundary

The canonical fingerprint hashes only the normalized source (without timestamp fields), resolved applicable inheritance, applicable capability, applicable threshold profile, applicable template values/version, rules version, and generator version. It excludes timestamps and unrelated rules, capabilities, thresholds, or global configuration. Runtime, review, and translation artifacts copy this exact fingerprint.

## Validation and workflow authority

`npm run validate:exercise-schemas` applies the repository's closed Draft 2020-12 schemas to normalized sources, canonical profiles, runtime adapters, translation sources, the capability registry, and the generated manifest. `npm run validate:exercise-semantics` blocks capability, camera, landmark, threshold, unsupported-claim, workflow, duplicate-authority, runtime-parity, and fingerprint failures that structural schemas cannot express.

Generation always emits `draft` / `pending` workflow state. It cannot approve or publish an exercise and cannot overwrite trainer decisions. Review artifacts remain detached from production authority.

## Challenge-system boundary

The runtime adapter declares compatibility with a session recorder and normalized pose trace. This is an integration contract only: generation provides stable exercise identity, versions, capabilities, thresholds, and fingerprinting for a future pose-capture pipeline. No challenge, rep counting, session recording, comparison, replay, personal-best, or leaderboard behavior is implemented here.
