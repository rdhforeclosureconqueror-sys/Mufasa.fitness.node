The goal is a SMART_ANALYST role that turns sourced market and product evidence into a traceable recommendation. It combines customer insights, marketing analytics, and conversion diagnosis inside the existing Business OS. Gold and Platinum are project acceptance levels, not industry credentials or promises of profitable campaigns.

Scout discovers candidates. Analyst evaluates evidence and identifies the next question. Experiment Manager designs and interprets the controlled test. Economics supplies authoritative financial assessments. Learning proposes changes. Management prioritizes work. All roles use one shared runtime and canonical records.

The owner's Fire → Earth → Metal language is a project metaphor: learn and define, construct and verify, then separate reusable components for distribution. It does not substitute for technical evidence or certification.

## What this first PR delivers

- A0–A8 scope, dependencies, ownership, and definitions of done.
- Reproducible baseline findings and a current-main reference.
- Assessment, evidence, calculation, judgment, tool, feedback, and certification requirements.
- Forty-two concrete acceptance scenarios with expected behavior, plus independent holdout evaluation requirements.
- A coding handoff and phase report format.
- Canonical readiness cards and machine evidence for planning only.

This PR does not implement the Analyst package, repair runtime diagnostics, connect accounts, run Test A, deploy, or certify a live role. Scenario specifications are not executable scenario results. Planning readiness is distinct from implementation readiness.

## Integration principle

Add the Analyst specialization to the existing coordinator, runtime, model gateway, evidence system, execution registry, Academy, and Command Center. Deterministic policy and measurement helpers are permitted; a second model client, authority engine, event store, private memory, or role-to-role execution chain is not.

The full planned analytical architecture is the build target. One fitness body is the first proof path. Unimplemented external connections remain explicit operational gaps, rather than reasons to remove analytical requirements.
